# 扫地机与原生版对齐

对应 [Issue #1](https://github.com/iPocket-APP/MijiaLAN/issues/1)。Rust 原先只导出了风速属性，没有接入清扫、停止和回充动作。本次按原生 Swift 实现补齐协议、桌面动作和 HomeKit 映射。

- 同时具有可读状态、开始清扫与回充动作的设备，家庭 App 提供一个主开关：开＝开始清扫，关＝回充。暂停或待机时显示为关，但再次关闭仍会下发回充；已清扫时再次开启、已回充时再次关闭不会重复发送命令。
- 状态按各型号规格的英文描述解释，不能把状态数字通用化。例如 C1 的 2 是清扫，V19 的 2 是暂停。离线、缺失或未知的 MIoT 状态向家庭 App 返回不可用。
- 开始、停止、暂停、仅扫地、扫拖、仅拖地及回充只在服务名称与零输入规格明确匹配时开放；原风速预设、增减控制和扫拖模式保留。缺少组合条件时保留单独的动作开关。房间、分区及其他厂商参数动作继续隐藏。
- 收到动作确认后最多读回六轮状态，每轮间隔 350 ms；只重读，不重发动作。状态未确认、设备拒绝或结果不明时返回失败。建图、洗拖布等离开静止状态的准备步骤按原生规则确认。
- `rockrobo.vacuum.v1`、`roborock.vacuum.c1`、`roborock.vacuum.e2`、`roborock.vacuum.s5` 使用明确映射的 `get_status`、`app_start`、`app_stop`、`app_charge`、`set_custom_mode`。仅第一代 `rockrobo.vacuum.v1` 回充前执行一次 `app_pause`；响应异常立即终止，不套用到未知型号。

验证使用 C1 与 V19 规格、仅监听 127.0.0.1 的加密 miIO 端点、内存凭据和独立 HAP 控制器。覆盖动作筛选、跨型号状态、延迟确认、重复命令防护、旧协议读写、家庭配对、主开关读写、暂停后回充及保留的属性控制；原台灯、其他设备和 HAP 数据库回归检查同时通过。

本轮未连接真实扫地机，不能将协议测试等同于所有型号的实机验收。已有桥身份和配对不重置；家庭 App 是否立即刷新新增服务取决于其配件缓存。
